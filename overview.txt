# ThunderByte Pterodactyl Theme — Continuation & Safety Guide

## 1. Project Overview

This project customizes a Pterodactyl Panel into a premium hosting panel branded as **ThunderByte**.

### Main panel

* Panel path: `/var/www/pterodactyl`
* Panel URL: `https://free.thunderbyte.bond`
* Main website: `https://thunderbyte.bond`

### Brand

* Brand name: **ThunderByte**
* Designer credit: **Designed by BrineAjay**

### Current visual direction

The desired theme is:

* Premium
* Modern
* Dark
* Dark blue / black
* Glassmorphism
* Subtle blue glow
* Minecraft hosting aesthetic
* Professional rather than overly bright
* Responsive on desktop and mobile

Do NOT turn the panel into a completely bright-blue interface.

# 2. VERY IMPORTANT SAFETY RULE

This panel was previously broken by an incorrect TypeScript/TSX modification.

A previous bad edit caused:

```text
SyntaxError: LoginFormContainer.tsx
Missing semicolon
```

and earlier edits also caused a Laravel 500 error.

Therefore:

## NEVER blindly replace large blocks of TSX.

Before modifying a source file:

1. Inspect the actual current file.
2. Make a backup.
3. Identify the exact block.
4. Replace only that block.
5. Verify the resulting file.
6. Run the production build.
7. Only then continue to another file.

Do not assume the file has the same contents as an earlier chat.

# 6. Build Command

After changing frontend TypeScript/TSX/CSS files, use:

```bash
cd /var/www/pterodactyl && yarn build:production
```

A successful build should end with something similar to:

```text
webpack ... compiled successfully
Done
```

Do NOT consider a theme edit complete if the production build fails.

---

# 7. Build Warnings

The build may display warnings such as:

```text
[baseline-browser-mapping] The data in this module is over two months old.
```

or:

```text
Browserslist: browsers data (caniuse-lite) is 10 months old.
```

or:

```text
(node:...) [DEP0180] DeprecationWarning
```

These warnings are not automatically build failures.

The important part is whether Webpack ends with:

```text
compiled successfully
```

If it says:

```text
ERROR in ...
Module build failed ...
```

STOP and fix the source error before doing anything else.
