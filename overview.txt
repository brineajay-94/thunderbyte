# ThunderByte Pterodactyl Theme — Safe Workflow & Error Prevention Guide

> **Purpose:** This document is the mandatory workflow for continuing the ThunderByte Pterodactyl theme project in a future chat.
>
> **Primary goal:** Make visual/theme changes without causing Laravel 500 errors, broken TSX/TypeScript, failed Webpack builds, broken Blueprint functionality, or loss of the working panel.

---

# 🚨 1. MOST IMPORTANT RULE

## NEVER MODIFY THE PANEL BY GUESSING.

Every future change must follow:

```text
IDENTIFY
   ↓
INSPECT
   ↓
BACKUP
   ↓
EXACT EDIT
   ↓
VERIFY
   ↓
BUILD
   ↓
TEST
```

Never do:

```text
GUESS FILE
   ↓
GLOBAL REPLACE
   ↓
BUILD
   ↓
HOPE
```

# 7. NEVER USE GLOBAL REPLACEMENTS

Do NOT run commands such as:

```bash
grep -Rl "Pterodactyl" . | xargs sed -i 's/Pterodactyl/ThunderByte/g'
```

Do NOT globally replace:

```text
Pterodactyl
pterodactyl.io
Pterodactyl Software
Blueprint
```

These names may exist in legitimate application code.

Global replacement can break:

* routes
* APIs
* package names
* configuration
* update systems
* Blueprint
* dependencies
* documentation
* application logic

Only change the specific visible UI component.

# 8. BACKUP BEFORE EDITING

Before modifying a source file:

```bash
cp FILE /root/FILE.before-change-$(date +%Y%m%d-%H%M%S)
```

Example:

```bash
cd /var/www/pterodactyl && \
cp resources/scripts/components/auth/LoginFormContainer.tsx \
/root/LoginFormContainer.tsx.before-change-$(date +%Y%m%d-%H%M%S)
```

This creates a separate emergency copy.

---

# 9. INSPECT BEFORE EDITING

Never write a replacement before seeing the current file.

Example:

```bash
cd /var/www/pterodactyl && \
sed -n '1,140p' resources/scripts/components/auth/LoginFormContainer.tsx
```

For a specific section:

```bash
cd /var/www/pterodactyl && \
grep -n -B10 -A20 -E 'Pterodactyl|ThunderByte|BrineAjay|Attribution' \
resources/scripts/components/auth/LoginFormContainer.tsx
```

The exact current code must be used for the replacement.

---

# 10. EXACT-BLOCK REPLACEMENT ONLY

Preferred method:

```text
old exact block
        ↓
new exact block
```

The script must refuse to edit if the expected block is not found.

Example:

```python
from pathlib import Path

p = Path("FILE")
s = p.read_text()

old = """EXACT CURRENT CODE"""

new = """EXACT NEW CODE"""

if old not in s:
    raise SystemExit(
        "ERROR: Expected block was not found. "
        "NO CHANGES WERE MADE."
    )

p.write_text(s.replace(old, new, 1))

print("SUCCESS: Exact block replaced.")
```

This is much safer than broad `sed` commands.

---

# 11. NEVER FORCE A FAILED REPLACEMENT

If you see:

```text
ERROR: Expected block was not found.
NO CHANGES WERE MADE.
```

STOP.

This means the current source is different from what was expected.

Do not:

* remove more text
* use a larger regex
* replace the whole file
* guess the structure

Instead:

```text
Inspect current source
        ↓
Find actual block
        ↓
Create new exact replacement
```

# 12. TSX / TYPESCRIPT SAFETY

TSX files are especially sensitive.

A syntax error reported here:

```tsx
forwardRef<HTMLFormElement, Props>
```

does NOT necessarily mean that line is wrong.

The actual problem may be above it.

Common causes:

```text
Missing >
Missing </tag>
Missing }
Missing )
Missing ]
Broken JSX
Broken string
Broken template literal
Text accidentally inserted outside JSX
```

If Webpack reports a TSX syntax error:

## STOP ALL FURTHER EDITS.

Inspect the entire surrounding section.

Example:

```bash
cd /var/www/pterodactyl && \
sed -n '1,100p' resources/scripts/components/auth/LoginFormContainer.tsx
```

# 37. ONE-COMMAND REQUIREMENT

The user prefers copy-pasteable commands.

A command may contain multiple safe steps, but it must:

1. Enter the correct directory.
2. Create a backup.
3. Verify the expected source.
4. Perform an exact replacement.
5. Verify the result.
6. Build.
7. Stop if anything fails.

```bash

```

or equivalent error handling when appropriate.

A failed step must not silently continue.
